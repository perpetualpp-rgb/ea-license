# แผนพัฒนา Order Flow Lab → แอปสมาชิกรายเดือน

สถานะวันที่ 18 ต.ค. 2026 · เอกสารนี้เป็นแผนทำงาน ไม่ใช่คำปรึกษากฎหมาย

## 1. ตอนนี้มีอะไรแล้ว

| ส่วน | สถานะ | ข้อจำกัด |
|---|---|---|
| engine คำนวณ (CVD, กำแพง, ไม้ใหญ่, profile, VWAP) | มีทั้ง Python (`engine/`) และ JS (`web/engine.js`) ผลตรงกันทุกตัวเลข (มีเทสต์) | — |
| หน้า desk (`desk/`) | ใช้งานส่วนตัวได้ กราฟเลื่อน/ซูมแบบ TradingView, แผนเทรด, บันทึกผล | ดึงข้อมูลผ่าน connector ของ claude.ai ในบัญชีเจ้าของ **ขายให้คนอื่นไม่ได้** ข้อมูลเริ่มใหม่ทุกครั้งที่เปิดหน้า |
| collector (`collector.py`) | เก็บ REST ของ OKX / Kraken / Coinbase ลงไฟล์ | ยังไม่มี Binance, ไม่ใช่ WebSocket, ไม่ได้รัน 24 ชม. |

ข้อสรุปสำคัญ: แอปสำหรับลูกค้าต้องมี **server ของเราเอง** ที่เก็บข้อมูลตลอด 24 ชม.
และส่งผลคำนวณให้ลูกค้า ลูกค้าไม่ควรดึงข้อมูลจาก exchange เองทีละคน

## 2. สถาปัตยกรรมเป้าหมาย

```
Binance WebSocket ──► Collector (Python asyncio, 24 ชม.)
  aggTrade, depth diff,      │  สร้าง order book ในหน่วยความจำ
  kline 1m, markPrice        │  ใช้ engine/ เดิมคำนวณกำแพง, ไม้ใหญ่, CVD, footprint
Binance REST (OI ทุก 5 นาที) │  คำนวณแผนเทรดและบันทึกผลแผนตลอด 24 ชม.
                             ▼
                 ฐานข้อมูล time-series (TimescaleDB)
                 trades, book ราย 1 วิ (รวมเป็นช่วงราคา), wall events, แผน + ผล
                             │
                 API + WebSocket gateway (FastAPI)
                 ตรวจสิทธิ์สมาชิก (JWT) ก่อนส่งข้อมูลทุกครั้ง
                             │
          เว็บแอป / PWA (ใช้หน้า desk เดิม + Lightweight Charts)
          ระบบสมาชิก + จ่ายเงิน + แจ้งเตือน (Telegram / LINE)
```

เหตุผลของแต่ละทางเลือก:

* **Python + engine เดิม** มีเทสต์ 51 ข้อ และ engine.js ฝั่งหน้าเว็บให้ผลตรงกัน จึงไม่ต้องเขียนใหม่
* **TimescaleDB (PostgreSQL)** ฐานเดียวเก็บได้ทั้งข้อมูลตลาดและข้อมูลสมาชิก เหมาะกับทีมคนเดียว
  ถ้าข้อมูลเกินราว 50 ล้านแถวต่อวัน ค่อยย้ายเฉพาะ trades ไป ClickHouse
* **WebSocket gateway ของเราเอง** ลูกค้าทุกคนเห็นข้อมูลชุดเดียวกัน ไม่ชน rate limit ของ exchange
  และคุมสิทธิ์ตามแพ็กเกจได้
* **ระบบสมาชิกแบบ managed** (เช่น Supabase Auth) รองรับ email / Google และต่อ LINE Login ผ่าน
  OpenID Connect ได้ ไม่ต้องเขียนระบบรหัสผ่านเอง

### ปริมาณข้อมูลโดยประมาณ (วัดจาก Binance วันที่ 16–18 ต.ค. 2026)

| ข้อมูล | ปริมาณ | พื้นที่ต่อเดือน (หลังบีบอัด) |
|---|---|---|
| XAUUSDT trades | 3,000–26,000 รายการ/ชม. วันหยุด, 45,000–100,000 รายการ/ชม. วันทำการ | ~1–3 GB |
| BTCUSDT spot trades | 22,000–110,000 รายการ/ชม. | ~3–6 GB |
| order book รวมเป็นช่วงราคา ทุก 1 วิ (ช่วง ±1%) | ~1.5 KB/วิ ต่อสินทรัพย์ | ~4 GB |
| แท่ง 1 นาที, OI, funding, wall events, แผน | เล็กมาก | < 0.5 GB |

เครื่อง 4 vCPU / 8 GB RAM / ดิสก์ 160 GB พอสำหรับ 2–4 สินทรัพย์ในปีแรก

## 3. แผนเป็นระยะ

### ระยะ 0: เก็บข้อมูล 24 ชม. (สัปดาห์ที่ 1–2) ← เริ่มเร็วที่สุด
ยิ่งเริ่มเก็บเร็ว ยิ่งมีสถิติจริงไว้ใช้ตอนขาย

1. collector แบบ WebSocket สำหรับ XAUUSDT perp, BTCUSDT perp และ BTCUSDT spot
   (aggTrade, depth diff ที่ซิงก์กับ snapshot, kline 1m, markPrice) + OI ทุก 5 นาที
2. ระบบบันทึกผลแผนย้ายมาไว้ที่ server ทำงาน 24 ชม. ไม่ต้องเปิดหน้าค้าง
3. ตรวจช่วงข้อมูลขาด, เชื่อมใหม่อัตโนมัติ, สำรองข้อมูลทุกวัน, แจ้งเตือนเมื่อ collector หยุด
4. ทดสอบว่า IP ของ server เรียก Binance ได้ (Binance บล็อก IP บางประเทศ เช่น สหรัฐฯ)

เกณฑ์ผ่าน: เก็บข้อมูลต่อเนื่อง 14 วัน ขาดหายไม่เกิน 1%

### ระยะ 1: พิสูจน์ว่าสัญญาณใช้ได้จริง (สัปดาห์ที่ 3–8)
1. replay ข้อมูลที่เก็บผ่าน engine เพื่อ backtest กฎแผนเทรด แยกข้อมูลชุดฝึกกับชุดทดสอบ
2. วัดผลแยกตามสินทรัพย์ สไตล์ ช่วงเวลา (เอเชีย/ลอนดอน/นิวยอร์ก) และช่วงข่าว
3. เพิ่ม footprint (ซื้อ×ขายรายราคาในแต่ละแท่ง) และการตรวจจับการดูดซับ (absorption)
4. เทียบสัญญาณจาก XAUUSDT กับราคา COMEX ว่าทำนายกันได้แค่ไหน

เกณฑ์ผ่าน: อย่างน้อย 100 ไม้ในชุดทดสอบ และ R เฉลี่ยเป็นบวกหลังหักค่าธรรมเนียม
ถ้าไม่ผ่าน ให้ขายเป็น **เครื่องมือวิเคราะห์** (ไม่มีจุดเข้า/SL/TP) แทน ดูข้อ 4

### ระยะ 2: แอป MVP + เบต้าฟรี (สัปดาห์ที่ 6–12)
1. เว็บแอป (PWA ติดตั้งบนมือถือได้) ใช้หน้า desk เดิมแต่รับข้อมูลจาก server ของเรา
2. สมัคร/ล็อกอินด้วย email, Google, LINE · ลืมรหัสผ่าน · ลบบัญชีได้เอง
3. ประวัติย้อนหลังเกิน 4 ชม. (ดึงจากฐานข้อมูล), บันทึกผลแผนรายคน, แจ้งเตือนเข้า Telegram / LINE
4. แพ็กเกจ: ฟรี (ข้อมูลหน่วง 15 นาที) / มาตรฐาน (สด) / โปร (สด + แจ้งเตือน + ประวัติยาว)
5. เบต้าปิด 10–30 คน ฟรี เก็บ feedback

### ระยะ 3: เปิดขาย (เดือนที่ 4 เป็นต้นไป)
1. ปิดประเด็นกฎหมายและสิทธิ์ข้อมูล (ข้อ 4) ก่อนเก็บเงิน
2. ระบบจ่ายเงินรายเดือน, ใบเสร็จ, ยกเลิกเองได้
3. หน้าแสดงสถิติผลแผนย้อนหลังแบบโปร่งใส พร้อมวิธีคำนวณ
4. monitoring, uptime, ช่องทางซัพพอร์ต

## 4. ความเสี่ยงที่ต้องปิดก่อนเก็บเงิน

กำลังตรวจกับแหล่งทางการ จะอัปเดตส่วนนี้พร้อมลิงก์อ้างอิง:

1. **สิทธิ์ใช้ข้อมูล TradingView:** ข้อมูลที่ดึงผ่านบัญชี TradingView ใช้ได้เพื่อดูส่วนตัวเท่านั้น
   (Terms of Use ข้อ 3) แอปสำหรับลูกค้าจึงต้องไม่ใช้ข้อมูลจาก connector tdv
2. **สิทธิ์ใช้ข้อมูล Binance เชิงพาณิชย์** (ข้อมูลดิบเทียบกับผลวิเคราะห์ที่คำนวณต่อ): รอตรวจ
3. **สิทธิ์ข้อมูล COMEX (CME):** แบบสด / หน่วงเวลา และค่าธรรมเนียมรายผู้ใช้: รอตรวจ
4. **ใบอนุญาต ก.ล.ต.** ถ้าขายแผนเข้า/SL/TP ของทองและคริปโต: รอตรวจ
5. **PDPA:** หน้าที่ขั้นต่ำของแอปที่เก็บข้อมูลสมาชิก: รอตรวจ
6. **ระบบรับชำระเงินรายเดือนในไทย** และช่องทางแจ้งเตือน (LINE / Telegram): รอตรวจ
