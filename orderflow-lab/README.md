# Order Flow Lab — เครื่องมืออ่าน order flow ทองคำและ BTC (ระยะ 1)

ห้องทดลองสำหรับสร้างเครื่องมืออ่าน order flow ของเราเอง ใช้ **ข้อมูลสาธารณะฟรี**
ทั้งหมด ไม่ต้องสมัครหรือใส่ API key รันด้วย Python 3 มาตรฐานล้วน ๆ (ไม่มี
numpy/pandas) เพื่อให้รันได้ทุกที่ รวมถึง cron ราคาถูก

> ระยะ 1 = เก็บข้อมูล + engine คำนวณ + รายงานบน terminal + **หน้าเว็บ dashboard แบบ static**
> พร้อม unit test ยังไม่มีระบบสมาชิก และ **ไม่ใช่คำแนะนำการลงทุน**

## แหล่งข้อมูลและข้อจำกัด (พูดตรง ๆ)

| สินทรัพย์ | แหล่ง | ได้อะไร | ทำฟีเจอร์ไหนได้ |
|---|---|---|---|
| **BTC** | OKX, Kraken, Coinbase (REST สาธารณะ) | order book หลายร้อยระดับ + trade ทีละรายการที่ระบุฝั่งผู้กดซื้อ/ขาย | **ครบ** CVD, กำแพง, big trades, volume profile, VWAP±σ |
| **ไฟล์แท่งเทียนใด ๆ** | ไฟล์ JSONL `{t,o,h,l,c,v}` ที่คุณมีสิทธิ์ใช้ | แท่งเทียน + volume | volume profile, Range/POC, VWAP±σ, เลขกลม, **CVD แบบประมาณ** (`report.py --bars`) |
| **โทเคนทอง** (XAUT, PAXG) | exchange เดียวกับ BTC | order book + trade เหมือน BTC | เหมือน BTC แต่เป็น **ตัวแทน** ของทอง ไม่ใช่ COMEX และตลาดบางกว่ามาก |

สิ่งที่ **ไม่มี** ในระยะนี้: order book และ tape ของ COMEX GC จริง (ต้องซื้อข้อมูล
ระดับ MBO) ทุกค่าที่คำนวณจากแท่งเทียนอย่างเดียวจะติดป้าย `approximate` ทั้งใน
JSON และในรายงาน

repo นี้ไม่เก็บข้อมูลตลาดของบุคคลที่สาม เทสต์ใช้ข้อมูลจำลอง (`tests/synth.py`) ·
ข้อมูลจาก TradingView ห้ามนำมาใส่ repo หรือใช้ทำบริการ: Terms of Use ข้อ 3 ให้สิทธิ์
แค่การแสดงผล และห้ามใช้เชิงพาณิชย์ · ก่อนเปิดบริการที่เก็บเงิน ให้ตรวจเงื่อนไข API
ของแต่ละ exchange ด้วย

## Indicator สำหรับ TradingView (`pine/order_flow_lab.pine`)

คัดลอกทั้งไฟล์ไปวางใน Pine Editor ของ TradingView แล้วกด "Add to chart"
ทำงานบนกราฟในบัญชีของคุณเอง ข้อมูลไม่ออกนอก TradingView

* **CVD ของ session** จาก footprint ของ TradingView (ต้องใช้แผนที่มี Volume Footprint)
  ถ้าบัญชีไม่มี footprint จะใช้ค่าประมาณจากแท่งเทียนแทน และตารางมุมขวาบอกไว้
* VWAP ±1σ/±2σ ของ session, POC / โซน 70% / แม่เหล็ก 30% ของ session ก่อน
* stacked imbalance (โซนลากไปทางขวาจนราคากลับมาแตะ), จุดปริมาณหนาแน่นรายระดับราคา,
  เลขกลม และสัญญาณ divergence ระหว่างราคากับ CVD
* ไม่มีกำแพงออเดอร์ เพราะ footprint คือการซื้อขายที่เกิดแล้ว ไม่ใช่ order book
* ทองคำ GC ใช้ค่าเริ่มต้นได้เลย (ชั้นละ 5 tick = 0.5 ดอลลาร์, เลขกลมทุก 25)
  BTC ให้เพิ่ม ticks ต่อชั้นและระยะเลขกลม (เช่น 500)

## หน้าเว็บ dashboard (`web/`)

หน้าเดียว ไม่มี server: เบราว์เซอร์ของผู้ใช้ดึง order book และ trade จาก API สาธารณะ
ของ OKX / Kraken / Coinbase โดยตรง (ทั้งสามเปิด CORS) แล้วคำนวณด้วย `engine.js`

* เปิดผ่าน GitHub Pages ของ repo นี้ที่ `/orderflow-lab/web/` (หลังรวมเข้า master)
  หรือรันในเครื่อง: `python3 -m http.server 8000` ที่โฟลเดอร์ราก แล้วเปิด
  `http://localhost:8000/orderflow-lab/web/`
* เลือกแหล่งข้อมูล (BTC 3 ตลาด / โทเคนทอง 3 ตลาด), ช่วงเวลา และขนาดแท่ง
* แสดง: แท่งเทียน + VWAP ±1σ/2σ + เลขกลม + ไม้ใหญ่ (วงกลมขนาดตามปริมาณ),
  volume profile แยกซื้อ|ขาย พร้อม POC / โซน 70% / แม่เหล็ก 30%, แถบกำแพงด้านขวา,
  กราฟ CVD, ตารางกำแพง (สถานะ/อายุ/ผลตอนหาย), โซนไม้ใหญ่ และ delta รายแท่ง
* รหัสสี: ฝั่งซื้อ/BID/แท่งขึ้น = เขียวทึบ, ฝั่งขาย/ASK/แท่งลง = แดงกลวง (รูปทรงเป็นตัวแยก
  ที่สอง สำหรับคนตาบอดสี) · รองรับโหมดมืดตามระบบ และปุ่มสลับ
* **ข้อจำกัด:** เริ่มเปิดหน้าจะมีข้อมูลแค่ trade ล่าสุด 500–1,000 รายการ (ไม่กี่นาที)
  แล้วค่อย ๆ สะสมขณะเปิดหน้าค้างไว้ ปิดแท็บ = ข้อมูลหาย ถ้าต้องการเก็บยาวใช้
  `collector.py` แทน · หน้าไม่ส่งอะไรไปที่ไหนนอกจากเรียก API ของ exchange

## ระยะ 0: เก็บข้อมูล Binance ตลอด 24 ชม. (`live/`)

ตัวเก็บข้อมูลแบบ WebSocket สำหรับวิจัยและ backtest ของเราเอง (ตามสิทธิ์ "internal use" ของ Binance)
ดู `ROADMAP.md` ข้อ 4.2 ก่อนนำข้อมูลไปให้คนอื่นใช้

* XAUUSDT และ BTCUSDT ฝั่ง futures รวมถึง BTCUSDT ฝั่ง spot: ทุกรายการซื้อขาย, order book ที่ซิงก์ตามวิธีของ Binance,
  แท่ง 1 นาที, mark price และ funding, Open Interest ทุก 1 นาที, และรายการ liquidation
* **`book` เป็นภาพสรุปแบบสุ่มเก็บ (sampled):** ทุก 1 วิ รวมปริมาณเป็นช่วงราคาภายใน ±1% ของราคากลาง
  ดูไม่ได้ว่าระหว่างวินาทีมีการเติม/ถอนอะไร ลำดับคิว หรือคำสั่งรายตัว ถ้าต้อง replay order book ละเอียด
  ระดับ 100 ms ให้ตั้ง `"store_depth_diffs": true` ใน `live/config.json` ระบบจะเก็บ depth diff ดิบทุกรายการ
  (พร้อม U/u/pu และเวลารับ) ใน stream `depth` และ snapshot ที่ใช้ซิงก์ใน `depth_snap` (ปิดไว้เป็นค่าเริ่มต้น
  เพราะ BTC ใช้พื้นที่หลาย GB ต่อวัน)
* หลุดแล้วต่อใหม่เองได้ trade id ที่ขาดระหว่างหลุดหรือปิดเครื่องจะเข้า **gap ledger** ใน `state.json`
  (ช่วง id, id ถัดไปที่จะดึง, จำนวนครั้งที่ลอง, สถานะ pending/partial/unrecoverable, error ล่าสุด) แล้วดึงย้อนหลังผ่าน REST
  ถ้าดึงไม่สำเร็จจะลองใหม่แบบเว้นระยะเพิ่มขึ้น (สูงสุด 5 นาที) ไม่ทิ้งช่วงนั้น และรีสตาร์ตแล้วทำต่อจากที่ค้าง
  id ที่ดึงไม่ได้จริง (ช่วงเกิน 300,000 id หรือ exchange ไม่ส่งมา) บันทึกเป็น unrecoverable และ meta `trade_gap` ไม่ข้ามเงียบ
* เก็บไฟล์ละ 1 ชั่วโมงต่อข้อมูลแต่ละชนิด แล้วบีบอัดเมื่อครบชั่วโมง ทุกไฟล์ที่บีบอัดมีบรรทัดใน `data/live/manifest.jsonl`
  (path, จำนวนแถว, ขนาด, sha256, เวลาแรก/สุดท้าย, เวลาปิด) ใช้ตรวจไฟล์สำรองได้ ทดสอบกับ BTC spot แล้ว order book
  ใช้พื้นที่ราว 9 MB ต่อวัน และรายการซื้อขายราว 8 ไบต์ต่อรายการ
* ความทนทาน: เขียนลงดิสก์ (fsync) ทุก 5 วิและก่อนปิดไฟล์ชั่วโมง ไฟดับอาจเสียข้อมูลที่ยังไม่ fsync ได้ราว 5 วิของทุก stream
  รายการซื้อขายช่วงนั้นดึงคืนได้ทาง REST แต่ book, แท่ง, mark, OI, liquidation ช่วงนั้นหายจริง และอาจมีแถวซ้ำ
  (อ่านแล้วให้ตัดซ้ำด้วย id/เวลา) การบีบอัดทำแบบที่ crash กลางทางแล้วกู้ต่อได้ (รายละเอียดใน `live/sink.py`)
* ไฟล์แบ่งตาม **เวลาที่ข้อมูลเข้ามา** ไม่ใช่เวลาเกิดเหตุ แถวที่ดึงย้อนหลังจึงอาจอยู่ในไฟล์ของวันถัดไป
  การอ่านต้องใช้เวลาในแถว (`row[0]`) และอ่านไฟล์วันข้างเคียงด้วย
* `data/live/status.json` อัปเดตทุก 10 วิ บอกว่าเชื่อมต่ออยู่ไหม, book ซิงก์ไหม, ข้อมูลล่าสุดมาเมื่อไร และ gap ledger

**ก่อนติดตั้ง ต้องตรวจว่าเครื่องเรียก Binance ได้** เพราะ Binance บล็อกบางประเทศ (เช่น สหรัฐฯ)
และ cloud บางภูมิภาค เปิด `https://fapi.binance.com/fapi/v1/ping` ในเครื่องนั้น ต้องได้ `{}`
ถ้าได้ข้อความ "restricted location" (รหัส 451) ให้ใช้เครื่องหรือ VPS ที่อื่น เครื่องที่บ้านในไทยใช้ได้

```bash
cd orderflow-lab
pip install -r live/requirements.txt
python3 -m live.collector                    # เก็บตลอด (Ctrl-C หยุด)
python3 -m live.collector --minutes 5        # ทดลอง 5 นาที
python3 -m live.check                        # สรุปความครบของข้อมูลเมื่อวานและวันนี้
```

`live.check` วัดแยกกันต่อ market/symbol/วัน UTC (เทียบกับช่วงที่ควรเก็บ ไม่ใช่ช่วงแถวแรกถึงแถวสุดท้าย):

* **ช่วงที่ควรมีข้อมูล** = ทั้งวัน UTC ถ้าเป็นวันนี้ตัดที่เวลาปัจจุบัน วันในอนาคตเป็น N/A
* **book** = จำนวนวินาทีที่มีแถว book ÷ วินาทีในช่วงนั้น พร้อมรายการช่วงที่หาย ≥ 60 วิ (เครื่องดับ, book resync)
* **kline** = จำนวนแท่ง 1 นาทีที่ปิดแล้ว ÷ จำนวนนาทีในช่วงนั้น (Binance ส่งแท่งทุกนาทีแม้ไม่มีการซื้อขาย
  จึงเป็นตัววัดว่า WebSocket ทำงานที่ดีที่สุด)
* **trades** = ความต่อเนื่องของ id ภายในช่วง id ที่เห็นในวันนั้น บอกแค่ว่าช่วงที่เห็นมีรูไหม **ไม่ใช่ uptime**
* **ความสด** = ข้อมูลล่าสุดของแต่ละ stream มาเมื่อกี่วินาทีก่อน และ **events** จาก meta: หลุด/ต่อใหม่, book resync,
  backfill ที่ต้องลองใหม่ และ id ที่กู้ไม่ได้
* วันที่ไม่มีข้อมูลเลยแสดง N/A ไม่ใช่ 100% ส่วน stream ที่ไม่มีแถวในวันที่ stream อื่นมีข้อมูลแสดง 0%

ให้รันตลอดเวลา เลือกอย่างใดอย่างหนึ่ง:
* **Docker บน VPS:** `cd orderflow-lab/live && docker compose up -d` (รีสตาร์ตเองเมื่อเครื่องบูต)
* **Linux ไม่ใช้ Docker:** ใช้ไฟล์ `live/orderflow-collector.service` กับ systemd
* **คอม Windows ที่บ้าน:** ติดตั้ง Python 3.12 แล้วสั่ง `py -m pip install -r live\requirements.txt`
  จากนั้นสร้างงานใน Task Scheduler ให้รัน `py -m live.collector` ในโฟลเดอร์ `orderflow-lab`
  ตอนล็อกอิน และปิดโหมด Sleep ของเครื่อง

สำรองข้อมูล: คัดลอกไฟล์ `.jsonl.gz` ใน `data/live/` ไปเก็บที่อื่นทุกวัน เช่น ใช้แอป Google Drive
บนเครื่องซิงก์โฟลเดอร์นั้น ไฟล์ที่ยังไม่ปิดชั่วโมงเป็น `.jsonl` ธรรมดาและกำลังถูกเขียนอยู่

## หน้า desk บน claude.ai (`desk/`)

หน้าเดียวกับที่เปิดใน claude.ai ดึงข้อมูลผ่าน connector **Binance** และ **tdv (TradingView)**
ในบัญชีของผู้เปิดเอง (ไม่มีข้อมูลตลาดฝังในไฟล์ นอกจากตาราง COT ของ CFTC ซึ่งเป็นข้อมูลสาธารณะ)

* ทองคำ Binance XAUUSDT (perp) และ BTC Binance spot: order book, รายการซื้อขาย และแท่งเทียนที่มี
  ปริมาณผู้กดซื้อจริง → Wall, Order Book (SD, เติม/ถอน), Big Trades Zone, CVD, Flow
* ทองคำ COMEX GC1! จาก TradingView: แท่งเทียนอย่างเดียว ค่าที่ได้จึงเป็นค่าประมาณ (≈)
* แผนเทรดอัตโนมัติ: เลือกโซนที่มีหลายระดับซ้อนกัน, SL = ขอบโซน + ATR รายวัน × 0.25 (เดย์เทรด)
  หรือ × 0.5 (สวิง), TP = แนวถัดไปที่ได้อย่างน้อย 1.5R/2.5R (สวิง 2R/3.5R)
* ขนาดไม้: ใส่ทุนและ % เสี่ยงต่อไม้ แผนจะคำนวณ oz / lot XAUUSD / GC / MGC / BTC ให้
* ข่าวเศรษฐกิจ US จากปฏิทินของ TradingView: เตือนข่าวแรงล่วงหน้า 2 ชม. และไม่นับไม้ใหม่ช่วง ±30 นาที
* Futures (Binance perp): Open Interest + การอ่าน OI คู่ราคา, Funding, Top trader Long/Short, Taker ซื้อ/ขาย
* บันทึกผลแผน (**ผลจำลองเพื่อวิจัยส่วนตัว** ไม่ใช่ฟีเจอร์สินค้าและไม่ใช่ผลเทรดจริง): กติกาอยู่ใน `desk/journal.js`
  ไฟล์เดียวที่ทั้งตารางแผนและตัวบันทึกใช้ ข้อความ "เงื่อนไขยืนยัน/ยกเลิกเมื่อ" สร้างจากกติกาเดียวกันจึงตรงกับที่ตรวจจริง
  ล็อกแผนเมื่อราคาใกล้โซน, เข้าเมื่อแท่งยืนยันปิดกลับและ TP1 อยู่ฝั่งกำไร ≥ 1R (วัดแบบมีทิศทาง), ตามผลด้วยแท่งที่ปิดแล้วเท่านั้น
  จนถึง SL (แท่งเปิดเลย SL = ออกที่ราคาเปิด) / ทุน / TP2 / หมดเวลา แท่งเดียวที่แตะทั้งฝั่งขาดทุนและฝั่งกำไรจนรู้ลำดับไม่ได้
  บันทึกเป็น "ไม่ชัด" พร้อม R แบบระวัง/แบบดี และไม่นับในสถิติหลัก ทุกไม้เก็บ `rule_version` และสภาพตอนเข้า
  (bias, ข่าว ok/unavailable ฯลฯ) สถิติแสดง TP1 hit rate และ R ก่อนต้นทุนของกติการุ่นปัจจุบัน โหลดบันทึกครบทุกหน้า
  เก็บใน `data/users/<id>/journal/trades` (ส่วนตัวของผู้เปิด)
* เรียก Binance ได้เฉพาะ 11 endpoint ข้อมูลตลาดที่อยู่ใน allowlist (`BIN_ALLOW` ใน `template.html`)
  คำสั่งซื้อขาย/โอน/leverage ถูกบล็อก

node desk/check.js      # เปิดหน้าด้วย connector จำลอง แล้วจับภาพไว้ที่ data/ (ต้องมี playwright)

### ข้อตกลงสำคัญ
* `Trade.side` คือ **ฝั่งผู้กดซื้อ/ขาย (taker)** เสมอ Coinbase ส่งฝั่ง maker มา
  parser จะกลับด้านให้ ถ้าพลาดตรงนี้ CVD จะกลับเครื่องหมายทั้งหมด
* ขนาดเป็นหน่วยของตลาดนั้น (BTC, PAXG, สัญญา) เกณฑ์ big trade ใช้ percentile
  จึงใช้ได้ทุกหน่วย
* กำแพง = ระดับที่ใหญ่กว่ามัธยฐานของ 200 ระดับใกล้ราคา ≥ 4 เท่า และอยู่ห่างจาก
  ราคาไม่เกิน 1% (ปรับได้ใน `config.json`) ภาพนิ่งภาพเดียวบอกไม่ได้ว่ากำแพงจริงไหม
  ตัวติดตามจึงบันทึกว่ามันอยู่นานแค่ไหน โตหรือหด และตอนหายไปราคาอยู่ไหน: "ราคาไปถึง" (`price_reached`)
  "หายไปก่อนราคาถึง" (`removed`) หรือ "ไม่ทราบ" (`unknown`: ไม่มี book ฝั่งนั้น หรือ book ขาดช่วง)
  order book แบบ L2 **บอกไม่ได้ว่าถูกซื้อขายจริง (filled) หรือถูกถอน** จึงไม่ใช้คำเหล่านั้น
  กำแพงที่เห็นแค่ครั้งเดียวแล้วหายถือเป็น noise ไม่บันทึก
